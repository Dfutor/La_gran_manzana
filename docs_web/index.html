API «La Gran Manzana» — Documentación para expositores

Inventario por lotes (FEFO) y consulta/recomendación de productos. Proyecto de Calidad de Software.

  • URL base: http://158.158.17.188
  • Colección de Postman: granmanzana.postman_collection.json (6 carpetas, 39 peticiones con pruebas automáticas)
  • Frontend de prueba: /granmanzana/

1. Probar en Postman paso a paso

  1. Descarga la colección con el enlace de arriba (clic derecho → Guardar enlace como… si el navegador la abre en vez de descargarla).
  2. Abre Postman (de escritorio o web) → botón Import → arrastra el archivo granmanzana.postman_collection.json.
  3. Aparece la colección La Gran Manzana - API. La variable base_url ya apunta a http://158.158.17.188; para cambiarla, haz clic en la colección → pestaña Variables.
  4. Una petición a la vez: abre cualquier petición (por ejemplo 1. Salud → Salud del API y MySQL) y pulsa Send. Abajo verás el JSON, el código HTTP y el tiempo; en la pestaña Test Results aparecen las pruebas superadas.
  5. Todas juntas: clic derecho en la colección → Run collection → Run La Gran Manzana - API. Corre las 39 peticiones en orden y muestra cuántas pruebas pasaron.
    Hay que correrlas en orden, porque unas guardan datos que usan las siguientes (por ejemplo, el id de la categoría creada).

La carpeta 3. Categorías crea categorías de prueba y al final las elimina, así que la base queda igual que antes. La simulación FEFO no modifica el inventario.

Probar a mano (sin importar la colección)

  1. En Postman: New → HTTP Request.
  2. Método GET, URL http://158.158.17.188/api/productos?q=gel → Send.
  3. Para un POST: método POST, URL http://158.158.17.188/api/categorias, pestaña Body → raw → JSON con {"nombre": "Mi categoría"} → Send. Repítelo para ver el 409 por duplicado.
  4. Para borrarla: método DELETE, URL http://158.158.17.188/api/categorias/ID (el id que devolvió el POST) → 204.

Lo mismo con curl

curl -i http://158.158.17.188/api/salud
curl -i "http://158.158.17.188/api/productos?q=gel"
curl -i "http://158.158.17.188/api/productos/1/plan-fefo?cantidad=40"
curl -i "http://158.158.17.188/api/recomendaciones?necesidad=3&evitar=13"
curl -i -X POST http://158.158.17.188/api/categorias -H "Content-Type: application/json" -d "{\"nombre\":\"Mi categoria\"}"
curl -i -X DELETE http://158.158.17.188/api/categorias/ID

3. Reglas de negocio

  • Stock vigente = suma de cantidad_actual de los lotes no vencidos. El stock no se guarda en la tabla productos.
  • FEFO (First Expired, First Out): se vende primero el lote que vence primero; en empate, el de menor id.
  • Ventana de alerta: lotes con existencias que vencen en los próximos dias_alerta_temprana días (120 por defecto).
  • Nivel: vencido si ya venció; liquidar si faltan ≤ dias_alerta_liquidacion días (60); si no, devolver.
  • Acción sugerida: vencido → retirar y registrar la baja; liquidar → rebaja, combo o venta destacada; devolver → devolución al distribuidor si el proveedor la acepta, si no, venta destacada.
  • Los productos inactivos no aparecen en ningún endpoint. La ficha siempre incluye el aviso de complemento (Decreto 3249 de 2006).

4. Formato de respuestas y errores

  • Todo es JSON en UTF-8. Las listas vacías son [], los valores faltantes son null, las fechas van como "AAAA-MM-DD".
  • Los errores tienen la forma {"error": "mensaje"}: 400 (dato inválido), 404 (no existe), 405 (método no soportado), 409 (conflicto: duplicado, en uso o stock insuficiente), 500 (error interno, con una referencia para ubicarlo en el log).
  • Cada respuesta trae la cabecera X-Request-Id, que también queda en el log del servidor.
  • Seguridad: todas las consultas SQL usan parámetros, así que un intento de inyección se guarda como texto. El API se conecta a MySQL con un usuario de permisos limitados.
